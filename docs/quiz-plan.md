## 二、两种模式 + AI

同一个题库两种用法（练习 / 模拟）；AI 讲解、AI 诊断是这两个模式里的功能（2.3）。AI 出题待定（2.4）：

| | 练习模式 | 模拟模式 |
|---|---|---|
| 用途 | 刷弱项、巩固语法点 | 摸底、练时间分配 |
| 选题 | 按题型 / 按课 / 错题本 / 随机 | 固定整卷（第 1、2、3 套…） |
| 反馈 | **每题即时**：对错 + 解析 + 链到课文 | **交卷后**才显示 |
| 计时 | 不计时（记录每题用时） | 105 分钟倒计时，可暂停（标"非正式"） |
| 振假名 | 解析里有；题干可开关 | 无（同真考） |
| 题量 | 每组 10 题，可连做 | 一套约 73 题 |
| 结果 | 正确率累计到题型 / 语法点 | 估算分 + 题型分析 + 时间分析 |

### 2.1 练习模式

> 详细规格（流程、各题型界面、抽题规则、错题本、存储）见 [quiz-practice-spec.md](quiz-practice-spec.md)。

**入口**
1. 练习页 → 选题型（漢字読み、文法形式…）或"错题本" / "随机 10 题"
2. 课文页 → 每个 `## N.` 语法点下面一个「练习这个语法点（3 题）」按钮，内嵌作答，不跳页

**一道题的流程**
题干 → 点选项 → 立刻标对错 → 展开解析（为什么对、每个干扰项为什么错、相关语法点链接）→ 下一题

**错题本**
- 答错自动加入；之后连续答对 2 次（间隔 ≥1 天）才移出
- 「错题重做」= 优先抽错题本里到期的题
- 后续可导出成 Anki（接现有 build-anki 的卡片格式）——第二期

**进度面板**（练习页顶部）
- 每个题型：做过 / 正确率 / 错题数
- 薄弱题型排序，一键"练最弱的"

### 2.2 模拟模式

> 详细规格（三种做法、计时与暂停、估算分、时间分析、复盘、数据格式）见 [quiz-mock-spec.md](quiz-mock-spec.md)。

**开考前**：选套卷 → 说明页（时间、题数、建议时间分配，引用 jlpt 指南页）→ 开始

**作答中**
- 顶部：剩余时间 + 当前大题（問題 N）
- 题号面板：已答 / 未答 / 标记（"待会回来看"）
- 可前后跳题；刷新或关页面后能接着做（进度存 localStorage）
- 时间到自动交卷；也可提前交卷（未答题会提示）

**交卷后**
1. **估算分**：言語知識 /60、読解 /60，各自对照 19 分单科线和 90 分总分线（只按两科算，页面写明"聴解未包含、等化计分无法精确还原，仅供参考"）
2. **题型表**：每个問題的正确数，标出低于 50% 的
3. **时间分析**：各部分实际用时 vs 建议用时（文字・语汇・语法 ≈ 30 分钟，读解 ≈ 70 分钟）
4. **逐题复盘**：每题的答案 + 解析，错题一键加入错题本
5. 历次成绩记录（同一套可重做，记最好成绩和最近一次）

### 2.3 AI（练习、模拟里的功能，不是单独的模式）

复用现有 AI 面板的调用层（`site/ai-assistant.js` 的 provider 配置、免费中转 / 自带 key），不另做一套。

**① AI 讲解**（练习模式答题后、模拟模式交卷后，每题都有）
- 打开 AI 面板，上下文自动带上：题干、选项、正确答案、**你选的答案**、是否"猜的"、固定解析、相关语法点那一节
- 第一条自动问"我选了 X，为什么不对"，之后可以自由追问
- 答题前 / 模拟作答中**不出现**
- 练习小结页另有「AI 总结这组错题」
- 详细规格：[quiz-practice-spec.md](quiz-practice-spec.md) §3.4

**② AI 诊断**（模拟卷结果页）
- 把题型得分、用时、错题对应的语法点和题型（不发整卷）交给 AI → 输出"接下来 1–2 周练什么"，每条带练习入口链接

**额度**
- 实测（Analytics Engine，10/20–10/27）：49 次请求，**0 次 limited、0 次 error**；平均每次约 127 neurons，峰值日 10/23 用 1,286 / 9,500（14%），含作者自己的请求。按这个均值，全站每天约够 75 次
- AI 讲解的第一条请求对同一题同一选项完全相同 → 命中 worker 已有的边缘缓存（3 天），不花 neurons；只有追问按普通问答计
- **第一期继续用免费中转（Workers AI），不换付费模型**；不额外设每日次数，沿用 worker 现有的每 IP 6/分钟、50/天
- worker 的 `source` 白名单加 `quiz-explain` / `quiz-summary` / `quiz-diag`，分开计数
- **升级触发条件**：AE 里开始出现 `limited`（全站额度被用完）→ worker 上游换成付费模型（DeepSeek Flash 或 Claude Haiku 5.5，按 §2.5 的对比测试选），key 放 worker secret，DeepSeek 预充值 / Anthropic 设消费上限兜底；换成 DeepSeek 时同步改 `pages/about.md` 的隐私说明

### 2.4 ⏸ AI 出题（待定，2026-10-28 决定先不做）

**是什么**：题库之外，按弱项现场出新题。固定题库每个语法点约 3 题，做两遍就记住答案了；AI 出题可以按错题本里的语法点、指定的课 / 题型、或自由输入（"考我 ものの 和 にもかかわらず"）每次出 5 道新题。

**如果做，怎么放**：不单独做模式，作为练习模式的「题目来源」：题库（已审核，默认）/ AI 出题（即时生成，标"未审核"）。做题 UI、判分、错题本完全复用练习模式。

**之前想好的设计**（留着，做的时候直接用）：
- 一次请求返回 5 道题的 JSON（同 §4.2 格式），解析只出当前界面语言，控制在 worker 的 MAX_TOKENS 2048 内
- 请求里带上目标语法点在课文里的那一节，让题目贴着笔记出，减少胡编
- 每题标「AI 即时生成 · 未经审核」+「我觉得答案不对」按钮（让 AI 重做这题并说明）
- 生成的题只存本地，答错进错题本标来源 `ai`
- 额度：估计 300–500 neurons / 次（未实测），免费中转每天约够 20–30 次；免费中转下每人每天 3 次，自带 key 不限次数，可选"出题后自动盲做校验"
- 讲解里的「再出 3 道类似的」快捷追问也一起等这个功能

**为什么先不做**：
- 题目质量是这个功能的命门，即时生成的题没法走 §4.3 的审题流程，答案错了会让学习者记错语法
- 12/6 前时间只够把审过的题库和 3 套模拟卷做好
- 题库 + 错题本 + AI 讲解已经覆盖"做错了弄懂"这件事；"题不够做"要等题库做完、自己刷过一轮才知道是不是真问题

**什么时候再考虑**：12/6 之后；或者自己刷题时发现题库题已经背下来、确实不够做。重启时先做 §2.5 的模型选型

### 2.5 出题模型选型（AI 出题重启时、或换付费模型前做；本地脚本，不碰网站）
- 同一份 prompt、同 20 个 N2 语法点，让候选模型各出 5 题：Workers AI gpt-oss-120b（现用）、DeepSeek Flash、Claude Haiku 5.5、Gemini Flash-Lite
- 用 §4.3 的盲做流程判合格率（答案对不上 / 有两个对的 = 不合格），取合格率够高的里最便宜的
- 参考价（每百万 token 输入 / 输出）：Haiku 5.5 $0.10 / $0.50（Anthropic 官方，prompt ≤100K）；DeepSeek Flash $0.14 / $0.28（第三方数据，充值前核对官方页）。Haiku 默认开思考，思考 token 按输出计价，出题时 effort 调 `low` 或关掉思考
- 现用的 gpt-oss-120b 也一起测：如果它合格率就够，连换模型都不用
- 这套脚本也可以用来**离线**批量出题库的初稿（离线出题后照样走 §4.3 审题），和线上 AI 出题是两回事

**不做**
- AI 生成整套模拟卷：读解文章长、题量大，额度扛不住，而且整卷未经审核没法当摸底用
- AI 判主观题 / 作文：JLPT 没有

### 3.2 N5–N2 各级别差异

题型 key 四个级别共用（漢字読み、表記、文脈規定、言い換え、文法形式、文の組み立て、文章の文法、读解各类…），每个级别用其中一部分；差别主要在考试结构和计分，做成**每级一份配置**，做题组件、练习页、模拟页的代码不分级别。

| 级别 | 考试节次（言語知識・読解） | 计分科目 | 合格线 | 课文语法点 |
|---|---|---|---|---|
| N2 | 105 分（文字・語彙・文法・読解 同一场） | 言語知識 60・読解 60・聴解 60 | 90，每科 19 | 85（L59–75） |
| N3 | 30 分（文字・語彙）＋ 70 分（文法・読解） | 言語知識 60・読解 60・聴解 60 | 95，每科 19 | 133（L35–58） |
| N4 | 25 分（文字・語彙）＋ 55 分（文法・読解） | 言語知識・読解 120・聴解 60 | 90；38 和 19 | 79（L18–34） |
| N5 | 20 分（文字・語彙）＋ 40 分（文法・読解） | 言語知識・読解 120・聴解 60 | 80；38 和 19 | 85（L00–17） |

（时间和合格线取自站内 JLPT 指南页；各级别每个問題的题数开工时对照官方公式問題集核对。）

对模拟模式的影响：
- **N3–N5 是两节**（文字・語彙一节、文法・読解一节）：模拟页按两节走，中间有"休息"页；可以只做其中一节（对应 N2 的"分部"做法，但 N3–N5 本来就分开，所以单做一节**算正式成绩的一半**，两节都做完才出整卷成绩）
- **N4/N5 的言語知識和読解合并计分**（/120，最低 38）：结果页按这个显示，"聴解需要几分"的算法跟着配置走
- 练习模式没有差别，只是题型列表按级别不同

**内容顺序**（2026-10-28 改为 N5 先行）：
- **N5 先行**：语法最简单、题最容易出准，用来把题目格式、审题流程、做题页、模拟页整套跑通；N5 也是读者最多的级别

### 4.2 数据格式

`questions/N2/<题型>.json`，模拟卷 `questions/N2/mock-1.json` 只存题目 id 列表。

```jsonc
{
  "id": "n2-bunpou-0012",          // 永久不变，进度 / 错题本按它记
  "level": "N2",
  "type": "bunpou-keishiki",       // 題型 key（対応 問題7）
  "stem": "雨が降っている（　）、試合は予定通り行われた。",
  "options": ["にもかかわらず", "からといって", "ばかりに", "あげく"],
  "answer": 0,
  "explain": {
    "zh": "…为什么选 1，2/3/4 各错在哪…",
    "en": "…"
  },
  "refs": ["lesson63#3"],          // 链回课文语法点（build 时校验存在）
  "passage": null,                 // 读解题：指向 passages/xxx.json
  "difficulty": 2,                 // 1–3，自评，用于抽题平衡
  "mockOnly": false,
  "verified": "2026-10-30"         // 通过审题流程的日期
}
```

### 4.3 出题和审题流程（质量是这个功能的命门）

1. **出题**：按题型模板生成，干扰项要求"真实考生会选错的那种"（形近、意近、接续错）
2. **盲做**：另一个 agent 只看题干和选项，不看答案，独立作答并给理由
3. **对账**：答案不一致，或者盲做时觉得有两个选项都对 → 打回重写
4. **机检**：build 时校验 `refs` 存在、选项不重复、答案下标合法、题干里有且只有一个空
5. **自用纠错**：做题时每题有「这题有问题」按钮 → 发 `gaEvent('quiz_report', {id})`，定期看

## 五、页面和技术

**页面**（每级 2 个 + 各自 /zh/ 副本，不做单题页面；N2 先上）

| URL | 内容 |
|---|---|
| `/n2-practice/` | 练习模式：题型选择 + 进度面板 + 错题本 |
| `/n2-mock-test/` | 模拟模式：套卷列表 + 说明 + 作答 + 结果 |
| `/n3-…`、`/n4-…`、`/n5-…` | 同上，每级 2 页；该级题库上线时才生成 |

每级单独页面而不是一个页面切级别：搜索词就是按级别搜的（"JLPT N5 practice test"），每级一个标题；进度和错题本是同一个 `jp_quiz_v1`，题目 id 带级别前缀，跨级别不冲突

- 页面骨架和说明文字由 build.js 生成（走现有模板、侧边栏、双语、SEO 标题）
- 题目放在 `dist/quiz/N2/*.json`，页面按需拉取；模拟卷答案和解析单独一个文件，交卷后才加载（不能在 HTML 源码里直接看到答案）
- 课文页的内嵌练习：build 时按 `refs` 把题目 id 写进语法点，点按钮再加载
- 题目 json 加 `?v=` 版本号，service worker 已有的 `*.js?v=` 缓存策略扩展到 json → 离线也能做题（通勤场景）
- 存储：localStorage `jp_quiz_v1`（每题作答历史、错题本、模拟卷进度和成绩），写入都包 try/catch
- 埋点：`quiz_start` / `quiz_answer` / `quiz_submit` / `quiz_report`，看完成率和题型

### 5.1 域名：放在 jpnotes.dev 下，不用子域名

不用 `test.jpnotes.dev`（或 `quiz.` 之类），直接 `jpnotes.dev/n2-practice/`、`/n2-mock-test/`：

- **localStorage 按域名隔离**：子域名上的错题本、进度和主站分开，课文页内嵌的「练 3 题」（在 jpnotes.dev 上）就写不进同一个错题本；读者在 AI 面板里存的 API key 也带不过去
- **SEO**：子域名在 Google 眼里接近一个新站，吃不到主站已有的一点权重；放在主站路径下，题库页和课文互相链接也算站内链接
- 构建、CSP、service worker、侧边栏、双语全部现成，不用再搭一套
- 播客用 `podcast.` 子域名是因为它是另一个仓库（Astro）；题库和课文共用数据和组件，不属于这种情况
- 另外 `test.` 一般会被理解成"测试环境"，不适合做正式入口

### 5.2 上线节奏：先能用，再放入口

build.js 加一个开关 `QUIZ_PUBLIC`：

| 阶段 | `QUIZ_PUBLIC` | 页面 | 入口 |
|---|---|---|---|
| 自用（11/3 起） | `false` | 照常生成，可直接打开网址；加 `noindex`，不进 sitemap | 无。自己存书签 |
| 公开（第 2 套卷做完后，约 11/17） | `true` | 去掉 `noindex`，进 sitemap，提交 IndexNow | 按下表全部加上 |

不需要单独的测试环境：本地 `npm run build` 预览 + 线上不公开的网址，够用。
